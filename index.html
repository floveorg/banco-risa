        Cultura

        Una historia de reírse a propósito

        Reír en grupo es tan viejo como la humanidad, pero convertirlo en ejercicio es reciente: en 1995, el médico Madan Kataria fundó en un parque de Bombay el primer club de la risa con cinco personas. Hoy hay miles en más de cien países.

        Del bufón medieval al clown hospitalario, de las comedias del arte a los memes: cada cultura ha guardado un rincón sagrado para la carcajada compartida.

        Ciencia

        Lo que dice la gelotología

        La ciencia que estudia la risa tiene nombre —gelotología— y bastantes datos. Reír no cura, pero mueve el cuerpo por dentro de forma medible.

        Hay incluso estudios que distinguen tipos de risa —de cosquillas, de broma, de alegría— y ven que activan zonas distintas del cerebro. Puedes escuchar sus muestras reales en la playlist «Risas del mundo».

        Techs

        Con qué está hecha

        Piezas pequeñas, estándares abiertos y coste cero: el proyecto corre sin servidor propio y cualquiera puede montar el suyo. Este sistema se replica al pie de la letra.

        Cloudflare R2

        Almacenamiento de objetos gratuito (10 GB). Cada audio se guarda como risa/b_*.mp3 y se sirve con URL pública.

        GitHub Pages

        La web es un solo HTML servido desde un repositorio público. Sin servidor, sin base de datos, sin coste.

        GitHub Actions

        Un cron en la nube llama al bot cada 5–10 minutos para vaciar la cola de subidas.

        Node.js + Telegram Bot API

        El bot recibe notas de voz, las normaliza con ffmpeg y las publica en el canal y en risa.json.

        Agentes — un prompt para montar el sistema

        La versión mini: un único prompt que convierte a un agente (IA) en el encargado de montar todo el sistema en tu proyecto. Cópialo, pégaselo y supervisa el resultado.

        Rol: asiste a montar el proyecto «mi proyecto», inspirándote en el proyecto libre github.com/floveorg/risa.

Objetivo: sistema completo — subida de audio · vídeo por Telegram → moderación → publicación en canal + feed web. Sin servidor propio.

Datos:
- Bot: @TuBot — cron Actions 5–10 min
- Contenido: audio · vídeo
- Feed: risa.json · newest-first
- Campos por pieza: título · etiquetas · autor.

Requisitos (release completa): piezas ≤ 1 min · ≤ 10 MB · máx. 5 en cola y 5 al día · CC BY-SA 4.0 («Enviar = consentir», tag «libre») · página de autor #/u/<key> con feed propio · comandos de solo lectura /me · /stats · /profile · /status · /queue · /latest · /now · /today · /since · /random · /trending · /play · etiquetas → chips · búsqueda · favoritos (filtro local) · entrada por deep link + QR · repo dedicado con Pages · feed risa.json newest-first.

Pasos:
1. Clona el repo de referencia; estudia bot/, index.html, risa.json y .github/workflows.
2. Pide y valida los secretos (BOT_TOKEN, CHANNEL_ID, MOD_GROUP_ID, credenciales R2) antes de usarlos.
3. Configura GitHub Actions como cron que llame a getUpdates cada 5–10 minutos.
4. Monta el feed risa.json y la web en GitHub Pages.
5. Verifica de punta a punta con una prueba real de audio · vídeo.

Permisos: leer/escribir el repo del proyecto, instalar dependencias de Node, desplegar Pages y Actions. Nada fuera del repo; confirma antes de crear credenciales.

Restricciones: sin servidor ni base de datos propios; piezas gratuitas (R2, Pages, Actions); respeta la privacidad (nunca guardar ids de Telegram en claro). Responde en español.

        El flujo completo, paso a paso:

        Las piezas

        1. Repositorio público — código, feed risa.json y la web, todo en un solo repo.
        2. Bot de Telegram — @BotFather te da el token y crea el bot.
        3. Canal + grupo de moderación — el canal publica; un grupo privado aprueba o rechaza.
        4. Cloudflare R2 — almacenamiento gratuito (10 GB) para los audios, con URL pública.
        5. GitHub Actions — un cron llama al bot cada 5–10 minutos para vaciar la cola.
        Qué ya funciona — las features técnicas de Risa v1

        La v1 ya trae esto funcionando, feature a feature, y cada pieza está escrita para una sola cosa: sin build, sin servidor y sin coste. Lo que queda se vive en la pestaña Desarrollo (v2).

        Web — el escaparate
        • App de archivo único: HTML + CSS + JS, sin build y sin dependencias
        • Servida desde GitHub Pages: estático, HTTPS, coste cero
        • Un solo feed (risa.json) como fuente de verdad de la web
        • Dos playlists (risas del mundo + risas de la gente) con un reproductor factory compartido
        • Reproductor inline: play/pausa, anterior/siguiente y lista de pistas
        • El feed puede incluir vídeo (mp4/webm) de otros bots sin tocar la web
        • «Últimas risas»: feed de las últimas n piezas (por defecto 6)
        • Chips de etiquetas filtrables
        • Nube de tags flotante con colisiones evitadas (floatChips)
        • Búsqueda por tag · título · nombre
        • Favoritos ❤️/⭐ compartidos por las dos playlists
        • Paginador del feed
        • Página de autor #/u/<key> con su propio feed
        • Hilos: cadenas de respuesta infinitas (parent) con conectores visuales y etiqueta del autor respondido
        • Subdominio de autor opt-in: username.liberada.net solo con «Sí, quiero» tras publicar (nunca automático)
        • Perfil agregador genérico: liberada.net/usa/<username>/ unifica risas + amas
        • Compartir por WhatsApp, Telegram, e-mail y copiar
        • QR del deep link t.me/RisaLiberadaBot para escanear
        • Imágenes y audio servidos desde R2 con URL pública (no desde GitHub)
        • Procedencia y licencia de cada pieza, enlazada a su ficha en Commons
        • Carrusel de beneficios de la risa (20 datos) que conecta con la sección ciencia
        Bot — el circuito serverless
        • Ingesta por Telegram: audios y vídeos de hasta 1 min
        • Límites duros: 10 MB por pieza, 5 en cola y 5 al día por remitente
        • Validación de tipo, extensión, tamaño y duración antes de subir
        • Offset persistido e idempotencia en getUpdates (ni pérdidas ni duplicados)
        • Long polling de 25 s: sin endpoint público y sin webhook
        • Cron de GitHub Actions como motor (cada 5–10 minutos)
        • Identidad al subir: nombre público, id de Telegram o anónima
        • Handle estable por palabra + hash salado (nunca @username)
        • Formulario guiado con botones inline: descripción, etiquetas y visibilidad
        • Reenviar clip del canal → cadena: detecta forward, propone respuesta, publica con parent
        • Ciclo detectado: hasAncestor() impide A→B→…→A
        • Normalización a MP3 con ffmpeg
        • Subida a Cloudflare R2 con firma SigV4 propia (cero dependencias)
        • La pieza aprobada antepone a risa.json (git como base de datos)
        • Commit + push automáticos del feed
        • Publicación en el canal público @risaliberada
        • Moderación humana en grupo privado: ✅ publicar, 🗑 borrar, ✏️ proponer detalles
        • Edición con visto bueno del autor: nadie publica contra su voluntad
        • Confirmaciones y avisos en español (subida, aprobación, rechazo, publicación)
        • Reconocimiento de decisiones por palabra («ok», «sí», «no», «borrar»…)
        • Mensajes malformados nunca tumban el bucle: parseUpdates es una función pura
        • Bienvenida con las reglas claras (1 min, 10 MB, 5 al día)
        • Cliente de Telegram con timeout y manejo de errores de red
        • Scripts de mantenimiento: migrate-r2.mjs y sync-media.mjs
        E · Comandos del bot — mínimos, de solo lectura y reproducción v1
        • Base: /me · /stats · /profile · /status · /queue
        • Exploración: /latest · /random · /now · /since · /today · /trending
        • Reproducción: /play (recorre el feed, el mismo que la web)
        • Perfil: /entrar (miniapp) · /mejorar (novedades) · /name (nombre público) · /usuario (subdominio) · /pub (mostrar @)
        • Todo es de solo lectura y reproducción: nada escribe; los comandos de perfil mutan solo en DM
        Moderación y confianza
        • Solo los moderadores del grupo pueden aprobar o rechazar
        • Nada se publica sin revisión humana (un par de ojos antes del canal)
        • Gate de aceptación: la edición propuesta se publica solo si el autor acepta
        • Certificación «autenticado en Telegram» en la página de autor (un moderador aceptó tu post)
        • Enlace a t.me solo con opt-in explícito (nunca automático)
        • Cuota y cola por remitente como anti-abuso
        • Licencia CC BY-SA 4.0 declarada en cada pieza publicada
        Página de autor — tag-url
        • Cada publicación genera su tag-url #/u/<key> automáticamente
        • El bot envía la URL de tu página en el aviso de publicación — funciona aunque solo añadas nombre público
        • Feed propio con todas tus risas
        • El reproductor de la página reutiliza el reproductor global
        • Enlace a t.me solo si hay opt-in
        • Avatar con inicial y fecha relativa (timeAgo)
        Privacidad y datos
        • Nunca se guardan ids de Telegram en claro en el repo
        • Origen oscurecido: el handle público es un hash salado de la identidad
        • Anónimo es una opción real al subir (y la más común)
        • Esquema risa.json versionado: id, t, name, tags, src, when, tg, key
        • Retrocompatible: el feed puede ser array (v1) u objeto {flag, clips}
        • Addons por flag: se activan desde la interfaz sin romper lo publicado
        • Feed agregable: puede sumar risas de otros bots (vídeo incluido)
        • Guardarraíles del contrato: las claves desconocidas de flove.json se ignoran
        Integración con flove
        • flove.json enriquece sin interrumpir: timeout de 4 s y fail-silent
        • Regla de oro: risa.json es la verdad; flove.json solo añade, nunca al revés
        • Al claim (v2), el enlace lleva al perfil único de flove donde ves tus risas y activas Lovy ya autenticado
        Infraestructura y hosting
        • Coste cero: R2 (10 GB gratis) + Pages + Actions
        • Sin servidor propio y sin base de datos: git + archivos
        • Secretos de GitHub Actions (BOT_TOKEN, CHANNEL_ID, MOD_GROUP_ID, R2_*)
        • Uploader R2 propio (SigV4) que sustituyó a Cloudinary por falta de permiso
        • Migración de prefijos y reescritura de URLs lista en migrate-r2.mjs
        • Medios sincronizados a R2 con sync-media.mjs (idempotente)
        • Replicable en una tarde: clona, lee el estándar, lanza tu bot, tu bucket y tu canal
        • El sitio se sirve dentro de flove.org, que además precachea offline (service worker)
        Calidad y documentación
        • Suite de tests node --test: 91 verdes sobre la lógica del bot y de la web
        • Ayudantes puros compartidos: risa.js corre igual en la web y en Node
        • Verificación con jsdom sin navegador (harness repetible)
        • Chequeo de sintaxis node --check en todos los archivos
        • Estándar RisaLiberada v1 documentado: flujos, datos, identidad, hosting y licencia
        • Diagramas mermaid (thread + flow) versionados junto al estándar
        • Plan de v2 centralizado en plan-v2.md del estándar
        • Vocabulario consistente: los nombres del código coinciden con el texto de la interfaz
        Accesibilidad y experiencia
        • prefers-reduced-motion respetado (animaciones off)
        • Teclado: flechas en carruseles, foco visible en chips y botones
        • aria-label y roles en los controles importantes
        • Contraste alto sobre crema/ink
        • alt descriptivo en todas las imágenes
        • Carga perezosa (loading="lazy") de imágenes
        • Audio con preload="none" (no descarga hasta reproducir)
        • Micro-interacciones solo con CSS, sin JavaScript de más
        • El botón de la risa reproduce un clip al toque (detalle audiovisual)
        • QR + deep link pensados para compartir desde el móvil

        El desarrollo continua con estas mejoras (añade al plan si no están ya):

        Mejoras que propone la v2

        • Perfiles más sólidos y extendidos. SQL via Service Workers de Cloudflare: datos locales rápidos, sin servidor propio, con sync offline.
        • Autenticación y protección de cuenta. Recoveries: mail, OAuth, browsy, nety… la identidad se respalda y recupera.
        • Integración con otras apps-bots. Liberada, Ama… la risa conecta estrictamente con el resto del circuito.
        • Playlists de favoritos. Con URL propia: comparte tu selección con un enlace.
        • Cadenas enriquecidas. Risas encadenadas con contexto: respuestas, hilos, historias.
        • Comandos avanzados. Más control desde el bot: gestionar, buscar, filtrar, ordenar.

        v2, extensión lineal de v1 — dos esquemas

        v2 no se instala al lado de v1: se enciende encima. Cada novedad aterriza sobre la etapa de v1 que potencia, y la web sigue leyendo el mismo risa.json.

        flove.json · cómo enriquece sin interrumpir

        Risa es autosuficiente: la web carga siempre su propio risa.json. Después, y solo después, hace una llamada opcional a flove.json que enriquece cuando responde y calla cuando no:

        • Enriquecimiento progresivo, fail-silent. Si flove.json falla (404, timeout, CORS), la web queda exactamente igual: sin enlaces, sin esperas, sin bloquear el feed.
        • Regla de oro. risa.json es la verdad del feed; flove.json solo añade. Nunca al revés.
        • Al claim (authy). Tu palabra reclamada se vuelve un enlace al perfil único de flove (flove.org/users/<key>/): ahí ves tus risas y al lado puedes activar Lovy ya autenticado — mismo authy, sin volver a loguearte.
        • Guarda-rrallas. Timeout de 4 s, se dispara tras renderizar el feed, lee solo claves conocidas (lo nuevo se ignora) y el contrato vive versionado en git: si se rompe, se pierde enriquecimiento, nunca risa.
